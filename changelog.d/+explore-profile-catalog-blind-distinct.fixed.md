**`explore profile` proves keys on Postgres views and tables nobody has analyzed.** On Postgres, a view (which `pg_stats` never describes) or a table built but never analyzed reported no distinct counts, so profiling came back with an unknown grain and no candidate keys even when a key was really there. Profiling now measures distinct counts for null-free columns with an exact scan inside the already confirmed budget, so a key that holds is proven, and the note says the counts were measured because the catalog had none instead of claiming they are unavailable until ANALYZE runs.
