**`dex transform repair <node>` drafts the override that repairs a failing package model.** It restates the package's SQL as a project model (package macros qualified, `var()` reads given the package's values, a relation var inlined so a project var cannot cycle, the package's materialization restated), disables the package's node in `dbt_project.yml` in place, and converts only the columns the warehouse error names, where the cached profile settles what they hold: all NULL is a cast through text, epoch seconds or milliseconds are read as such and flagged as meaning-changing, ISO text is parsed, and anything else is left `unresolved`. The draft is compiled and bound on dev reading no row before it is stored as an unapplied plan. A failed build's `completion.blockers[]` and `data.prerequisites[]` now carry a `next` line naming the repair, the refactor offer names the command instead of a key plans never emit, a `--for-plan` build of the repair carries `obligations.repair`, and the procedure treats repairing a blocker of the request's own deliverables as in scope.
