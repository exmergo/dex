**A plain `transform build` with a package enabled lists the project's own models first in `assurance`.** With the Elementary package enabled, a build also builds the package's ~30 models, and `assurance.build_only` (basis `built_models`) showed the package's tables first — the list is capped at five, so the project's own unasserted model was cut off and a reader saw only tables there is nothing to act on. The project's own models now come first in `assurance`'s name lists (`asserted`, `build_only`, and the failed checks), then package models, each group keeping the order the build ran them in; the counts are unchanged. The project is read off the manifest's `metadata.project_name`, so a caller that summarizes evidence without a manifest keeps the build's own order. A `--for-plan` build (basis `required`) is unaffected (#1500).
