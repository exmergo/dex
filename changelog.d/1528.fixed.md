**`maintain verify` holds a join to a declared `references` whatever the column's role, on a LEFT join too.** A `references` renders dbt's `relationships` test, which fails on any non-null value the parent lacks. `maintain verify` required the join only where the column was also declared `role: foreign_key`, so a `references` with no role, or with role `key` or `dimension`, on a LEFT join recorded its orphans as an optional relationship and withheld `join_orphans`: the build's test failed while verify called the same rows fine. A `references` now makes the join into the parent it names required on every join side, any non-null orphan contradicts it at the contract threshold (`threshold_source: contract`, `threshold: 0`, high), and NULL keys stay excluded, since a NULL is a missing reference both checks accept. A version label (`dim_teams.v2.team_id`) is matched to that version's relation, and a bare name to the version an unversioned `ref()` resolves to; before, a versioned parent was never matched. This can raise new `join_orphans` or `join_zero_overlap` findings on a project that declares `references` on LEFT-joined columns: each names the declaration it rests on under `required_by` (`<column> declares references <model>.<column>`), so it reads as the declaration's meaning, not a change in the model (#1459).
