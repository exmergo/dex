**The Cube writer now keeps a file's mode and holds an apply to the write-time rules.** `transform apply` of a Cube plan leaves an existing model file at its own mode (a new file gets the usual mode under the umask) instead of staging it owner-only through `mkstemp`, and apply runs the same `refusals_for` checks as `semantic cube define|update|plan`, so a plan document applied in another checkout cannot write content planning would have refused.
