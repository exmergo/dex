**`transform compare` refuses a seed or snapshot change only for the models that read it.** A plan that changed a seed returned `inputs_unsynchronized` for every model it rewrote, including ones with no path to the seed, so none of them could be compared. The check now reads the proposed model's own upstream graph: a model that does not read the project's changed seed or snapshot compares as usual and reports its real `input_scope`, and one that does is refused with a detail that names the file and says to plan it on its own, apply and build it, then plan the model edits again.
