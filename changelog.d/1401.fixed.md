**A derived semantic model names a column MetricFlow reserves instead of failing dbt's parse.** A declared mart column named for a time granularity (`year`, `month`, `day`, `week`, `quarter` and the rest, in any case) became a dimension, entity or measure of the same name, which MetricFlow refuses, so the plan warned with a raw dbt parse error. The derivation now fails before the parse, and `data.semantic_proposal.models.<model>` and the plan warning name each such column with the fix: rename the output column, or name the element `<model>_<column>` with `expr: <column>` and pass the definition to `semantic plan --definitions-file`.
