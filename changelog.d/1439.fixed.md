**A mart whose grain is a single time column now derives a semantic model dbt parses.** The primary entity took the column's name, the same as the time dimension, so dbt rejected the model in any project that defines a metric. The entity is now named `<model>_<column>` with `expr: <column>`, and a mart that references it joins by that name wherever the plan lists the two; a dimension of the child that already has the parent's entity name is renamed `<model>_<name>` with `expr: <name>` so the join name stays. Either replacement name is numbered when the model's own dimensions, entities or measures, or another element type anywhere in the semantic layer, already hold it.
