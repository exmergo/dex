**A mart whose grain is a single time column now derives a semantic model dbt parses.** The primary entity took the column's name, the same as the time dimension, so dbt rejected the model in any project that defines a metric. The entity is now named `<model>_<column>` with `expr: <column>`, chosen before the foreign keys so one that joins by the column's old name still joins. A plan settles every mart's primary entity name in a first pass, so a mart that references it joins by that name whatever order the plan derives them in, including marts that reference each other; a dimension of the child that already has the parent's entity name is renamed `<model>_<name>` with `expr: <name>` so the join name stays. Each replacement name, and a foreign key's fallback name, is numbered when the model's own elements, the entities its foreign keys join by, an entity name the layer or plan already uses, or another element type anywhere in the semantic layer or in another mart of the same plan already hold it.
