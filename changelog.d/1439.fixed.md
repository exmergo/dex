**A mart whose grain is a single time column now derives a semantic model dbt parses.** The primary entity took the column's name, the same as the time dimension, so dbt rejected the model in any project that defines a metric. The entity is now named `<stem>_<column>` with `expr: <column>`, where the stem is the model name without its layer prefix (`fct_`, `fact_`, `dim_`, `mart_` or `marts_`), so `fct_daily` with grain `output_day` gets `daily_output_day`. It is chosen before the foreign keys so one that joins by the column's old name still joins. A plan settles every mart's primary entity name in a first pass, then drafts the foreign entities that join an existing entity or a settled primary until the drafts settle, and resolves every foreign key in the plan against those drafts and the layer as it stands. A mart therefore joins the same name whatever order the plan derives them in, including marts that reference each other and a reference to a parent column that is itself a foreign key. A foreign key that cannot join what it references (the plan derives that column with no entity, or its entity is one this model already uses) is not derived, and says so, rather than offered under a name that joins nothing. A dimension of the child that already has the parent's entity name is renamed `<stem>_<name>` with `expr: <name>` so the join name stays. Each replacement name, and a foreign key's fallback name, is numbered when the model's own elements, the entities its foreign keys join by, an entity name the layer or plan already uses, or another element type anywhere in the semantic layer or in another mart of the same plan already hold it.
