**A list of personal data is screened as personal data.** `explore profile` now reads a list column's element type for its PII type gates, so `email VARCHAR[]` or a repeated BigQuery `ARRAY<STRING>` named like an email, name or phone column is flagged as a string column of that name is. Before, it was never flagged, so once profiled it read as cleared. On a SLayer layer, `<column>.value` was screened against an internal placeholder with the name heuristic instead of the list column's profile; it is now screened as the list column, so its profiled flag, confidence and any `pii_overrides` entry apply, and a refusal names `model.column.value`. A SLayer saved measure that answers with a column's values (`min`, `max`, `first`, `last`, SLayer 1.8's `collect`, or a model's custom aggregation) now has the columns it aggregates screened like grouped columns, so `collect(email.value)` is refused where grouping by `email.value` is. Mart derivation under `semantic.vendor: slayer` no longer declares a list as a scalar (`VARCHAR[]` as `TEXT`, `BIGINT[]` as `INT`): it writes `type: ARRAY` with the `element_type` the warehouse names.
