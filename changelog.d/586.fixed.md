**`DexConfig` built in code now warns on unknown keys and offers `.strict(...)`.** Programmatic callers constructing `DexConfig` or any target model via `DexConfig(...)` or `DexConfig.model_validate(...)` now populate `load_warnings` with the same unknown-key messages and nearest-key suggestions that `.dex/config.yml` loads produce, and `DexConfig.strict(...)` (or `model_validate(..., context={"strict": True})`) refuses unknown keys with `ConfigurationError`.
