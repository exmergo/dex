**Each test a declaration renders names the claim it checks.** The `unique`, `not_null` and `relationships` tests Dex writes from a declaration now carry `config.meta.dex.claim`, an id of the declared fact the test checks. A test's name and `unique_id` change with its model, column, arguments or `name:`, so the claim id is what to key incidents and "last verified" history on. It is a hash of the model's label, the declared field, its columns and its parameters, and never of the test's name, so two facts on one column get two ids. After the first render the file holds the id: declaring again or renaming the test leaves it as written, and a plan shows no diff on it. A test exactly as Dex rendered it before this release (the sampling flag, nothing else) gets its claim on the next render; a bare test stays bare (#1448).
