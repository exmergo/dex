**`maintain verify` judges a node's build status by the latest run that attempted it, and names that run on every build finding.** It read the `run_results.json` beside whichever `manifest.json` was newest, so a `dbt parse` after a Dex build (which rewrites the project's manifest and runs nothing) paired a fresh manifest with an older hand-run `dbt test` and reported a failure the build had since fixed, at high severity and with nothing to date it. Build status now reads every building run on disk (the project's target path and Dex's artifact directory, each with its `cold/`), ordered by dbt's `generated_at`. A compile is never read, a run no dbt log records is ignored with a warning, and a node the manifest no longer has is not reported. Because Dex's builds share one artifact directory and each replaces the last one's results, `transform build` now also keeps one entry per node in `dex_node_runs.json` beside them (status, invocation, time and command, never a dbt message), so a node an earlier Dex build passed is not judged by an older hand run. Each `node_failed`, `node_skipped` and `node_warned` carries `data.run` (`invocation_id`, `generated_at`, `command`, `artifact`, `cold`, `source`, `invoked_by` and `latest`), its `detail` names the run, and a failure from an earlier run than the latest says so. `data.build_status_runs` lists the runs read and ignored (#1524).
