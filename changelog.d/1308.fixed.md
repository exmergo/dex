**A passing Elementary test that checked nothing no longer makes a model `asserted`.** `transform build` counted any passing data test as a check of the model it reads, and an Elementary test can pass having read nothing: with the package's models disabled for the target, every test that checks `is_elementary_enabled()` compiles to the package's no-results query, and with them enabled, the anomaly tests, `schema_changes`, `volume_threshold`, `metric_stability` and `execution_sla` judge the run against history earlier runs stored and pass where it is missing, as on a fresh dev target. So a model whose only test was `volume_anomalies` read `asserted`. Such a pass now counts for no model, and `data.completion.assurance.unchecked_tests` lists each that reads a model the assurance covers (a deliverable, with `--for-plan`) with its `models` and a `reason_code`: `package_disabled` or `compiled_to_no_results` for a test whose compiled SQL is the no-results query (read from the build's manifest, so a project's own test wrapping one is caught too, and `collect_metrics`, which always compiles to it), and `history_unmeasured` for the history tests with the package enabled. A note in the build's warnings points at the list. A failing one still counts as a failed check, and dbt's own tests, the `*_with_context` tests, `json_schema` and `schema_changes_from_baseline` are never listed (#1308).
