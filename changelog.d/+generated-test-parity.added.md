**A composite grain is checked on every run, by a test Dex renders.** A model that declares a `grain` of two or more columns now renders `dex_unique_combination` on its YAML entry when `declarations.render_tests` turns it on, tagged `dex_every_run`. It fails when two rows share the grain, and agrees with `maintain verify`'s `grain_broken`: dbt's failure count is the same duplicate count, and a NULL in a grain column counts as a value on both sides. The test returns that count and never a key value, so Elementary keeps no key from a failing run. The plan that first renders it writes the test's macro into the project's macro paths as a reviewable diff; `transform macro dex_unique_combination` scaffolds or diffs it on its own. Each generated test states the connectors it supports, and on any other it renders nothing and the plan says `dialect_unsupported`; this one supports every connector (#1452, #1451).
