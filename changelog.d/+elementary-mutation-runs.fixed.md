**A mutation run leaves the dev warehouse alone in a project that installs Elementary.** `transform test --mutate` stripped `on-run-start` and `on-run-end` from the root `dbt_project.yml` only, and dbt also runs the hooks an installed package declares, so with Elementary installed every baseline and mutant run uploaded to its dev schema. The copy a mutation run works in now strips every installed package's run hooks too, disables Elementary's models unless something outside the package refers to one, and leaves Elementary's monitoring tests (anomaly tests, `schema_changes` and the others that check the package is enabled) out of every run. Each one left out is listed in `baseline.excluded` with status `not_run` and a `reason_code`, `elementary_disabled` or `elementary_history`. Where Elementary's models must stay enabled, the copy has dbt run the tests under its own test materialization, since Elementary's fails every test without the hooks that were stripped; where a test materialization in the project still hands them to Elementary's, the run is refused. The resolver also reads hooks that return before they read `edr_cli_run` as `return_early` where that var is written as Jinja, rather than `unknown` (#1307).
