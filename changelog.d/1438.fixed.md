**Project discovery no longer prefers a shallow project over a deeper one.** Discovery used to search only the repository root and its immediate children, so an example project one level down silently won over the real project two levels down, and every command then planned, built and verified against the wrong project. Discovery now also looks deeper (up to four levels down, skipping `dbt_packages`, `target`, virtual environments, `node_modules` and similar), and refuses with the existing multiple-projects error, naming the projects found and the `dbt_project_dir` setting to pin one, when it finds more than one. A repository whose only project is at the root behaves as before. A project at the root no longer hides a deeper one, so a root project with another project below it is refused as ambiguous too, and a symlinked alias of a project counts as that project once, not twice (#589).
