**The join-contract coverage probe resolves a model's key columns on Snowflake, Postgres and Redshift.** The probe that `transform build --verify` and `maintain verify` run quoted each join key column as the model's SQL spelled it, so on Snowflake a model written in lower case (`customer_id`) asked for a column the relation stores as `CUSTOMER_ID`, the statement was refused as an invalid identifier, and every such join came back `unchecked` with `reason_code: probe_refused`: `join_no_match`, `join_zero_overlap` and `join_orphans` never fired. Postgres and Redshift had the same defect for a model written in upper case. A key column not already spelled the way the connector folds unquoted names is now looked up in the relation's columns: a name the relation holds exactly keeps its spelling (a quoted mixed-case column), otherwise the folded name is used. A column the relation does not hold still comes back `probe_refused` with the warehouse's reason (#1366).
