**Databricks Metric Views read from Unity Catalog alone: `semantic.deployment: databricks_workspace`.** The Databricks counterpart of `snowflake_account`, read by `explore` only. `explore semantic list` lists every Metric View the source allowlist's scopes hold (`tables.list`, then `tables.get`, no SQL warehouse woken), validated as a file is, each named by its Unity Catalog name with per-view coverage (`full`, `limited`, `refused`); a name held in two allowlisted schemas is refused, naming both and `--scope`. `query` and `values` run through the same governed spine as `local`: dex renders `MEASURE()` and executes it under the cost guard and the PII gate, which still refuses before any SQL session opens. No file is needed, and nothing is held to one: every result carries `definition_source: account` and a warning that its definition was not checked against a reviewed file. A configured file describing a deployed view is named on it, and `--local` holds the deployment to it. `explore relationships|map --use-hosted-semantic-layer` fold the deployed views' joins and `rely` keys in, and the skill wrapper takes `[metric-views]` for that flag under this deployment.
