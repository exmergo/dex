**A versioned deliverable named by its file stem is `asserted` when a passing test checks it.** `summarize_completion` matched `assurance.asserted` by exact name, but `_checked` collects model labels (`dim_customers.v2`) while a `--for-plan` build names the deliverable by what the plan requires, which may be the version's file stem (`dim_customers_v2`): the deliverable was reported under `build_only` instead of `asserted`. Both sides are now matched through every name the node answers to, the way the unchecked-tests filter already does (#1308); the same mismatch on the failing side is fixed too, so a failing test on a versioned model lands under `failed_checks` with its check attached. The names listed stay the deliverable names, whichever name the plan uses, and the unversioned case is unchanged (#1499).
