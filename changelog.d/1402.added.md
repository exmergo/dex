**`transform compare` says when an input changed after the last build.** The baseline is the model's current SQL re-run on today's inputs, so rows loaded into a source, or a parent rebuilt, after the model's last build gave a baseline no build ever wrote, and a verdict such as `unexpected` could blame the change for what the new inputs did (#1387). The verdict now carries `data.baseline_never_built` with the build time and the evidence (`rebuilt_after`, the upstream models a later run rebuilt, and on DuckDB `row_count`, the built relation's count against the baseline's), plus a `warnings` line. The verdict itself is unchanged.
