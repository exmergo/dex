**An opt-in switch and a cadence tag for the tests Dex generates from declarations.** A new setting, `declarations.render_tests` in `.dex/config.yml`, decides whether a declaration renders Dex's generated tests, the ones that check a declared fact dbt's `unique`, `not_null` and `relationships` cannot. It is off by default, because those tests run in the project's production runs; `true` turns on every kind, and a list turns on the kinds it names, by test name or by cadence (`[dex_every_run]` for the cheap ones first). Every generated test carries a dbt tag fixed per kind, `dex_every_run` or `dex_scheduled`, so an orchestrator runs the whole-table scans on its own schedule with `dbt build --select tag:dex_scheduled` and leaves them out of every other run with `--exclude`. A plan lists each generated test its declarations give under `data.generated_tests`, with its tag, its claim and whether it rendered. The tests follow the facts the model's YAML declares, so on a project whose models were declared before the switch was on, `transform declare` proposes them without restating a fact. Turning the switch off removes no test already written. The built-in tests are unchanged and always render. No generated test ships in this release; each arrives with its own issue (#1449).
