**Build evidence no longer lists a skipped model's stale relation as generated, and an unrecognized node status can no longer read as `validated`.**
`data.evidence.generated` now lists only the relations of models, seeds and snapshots that succeeded in the run, so a relation an earlier run left behind is not reported as fresh when this run skipped its model (#1104). Node statuses are now read against an allow-list: `success`, `pass` and `warn` succeeded, `error`, `runtime error`, `fail` and `failed` failed, and `skipped` was not attempted. Any other status, such as a microbatch model's `partial success` or `no-op`, is unrecognized: it never counts as built, never validates, and is not reported as a failure. The new outcome `indeterminate` says so, `data.completion.deliverables.unrecognized` names such a deliverable, and `transform compare` treats a parent on such a status as not rebuilt. A required node that is present without succeeding, beside passing nodes and with nothing failed, now makes the outcome `partial`, agreeing with `coverage.not_built` (#1105). Downstream-visible: hosts that store `generated`, or recompute and compare outcomes, will see the new values, and `verify_build_evidence` now refuses a document claiming `validated` over an unrecognized status. A new conformance vector covers `indeterminate`, a forged vector covers that refusal, and the `build-skipped` vector's `generated` is now empty.
