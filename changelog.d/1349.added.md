**`maintain coverage --mutate` refreshes stale and missing mutation scores, and coverage lists the columns singular tests read.** `--mutate` runs `transform test --mutate` for each model whose recorded score is `stale` or `missing`, in selector order (else missing first, upstream first), at most 25 per run (`--max-models` narrows), and reports what it did under `data.refresh`. On a metered connector the whole batch is priced and confirmed once, each run draws on what the budget has left, and the models it did not reach are `not_run`; it is free on DuckDB, dev target only, and refused in values-free mode. Without `--mutate` the command still opens no connection. A model with no SQL to plant a defect in is now recorded and reads `untestable` until it changes, so a refresh always moves on. Each resource's `columns.referenced_columns` lists the columns its singular tests read, with the role each is read in (`predicate`, `join`, `aggregation`, `grouping`, `projection`), counted apart as `columns_referenced_only` and never as asserted; `data.singular_tests` names every test that could not be read, with a reason code.
