**`transform compare` names a held DuckDB lock instead of blaming the model.** When another `DexEngine` in the same process, or another process, held the dev DuckDB file open, dbt could not open it to compile and the comparison came back `baseline_not_compilable`, pointing at the SQL and at `dbt compile`. It is now `not_checked` with `reason_code: dev_target_locked` and a fixed detail naming the held connection, and that verdict is not recorded on the plan. On DuckDB, `transform build` now releases the engine's connection when the build finishes, with or without `--verify`, as `transform compare` already did, so a second engine in the same process can compare or build against the same file without the first calling `close()`; an engine that ran `explore`, `transform plan`, `transform repair` or `transform test` still holds its handle until it is closed.
